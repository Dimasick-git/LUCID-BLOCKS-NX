Сетевые проверки запускались в настоящем движке игры, с отдельными пользовательскими каталогами. IP партнёров не передавались тесту. Пустой изолированный мир использовался для воспроизводимости; это не замер FPS тяжёлого игрового мира. Исходная Windows-библиотека gdblocks в этих запусках не заменялась ARM64-библиотекой Switch.

Причина аппаратного вылета NSP05: `Node3D::get_global_position → Chunk::get_block_index_at_global → World::get_block_type_at`, нулевой указатель на чанк. Исправление находится в нативном патче `patches/gdblocks-switch-memory.patch`. Оно собрано для ARM64; устранение вылета ещё нужно подтвердить на консоли.

Отдельный синтетический снимок с 32 массивами по 16384 блока: бинарное кодирование, gzip и декодирование вместе заняли 11,4 мс; только JSON-подготовка — 79,6 мс на этом ПК. Эти числа не описывают FPS Switch.

В настольном GLES-рендере остаются сообщения исходного ограничения буфера instance uniforms (4096); сетевые тесты отклоняют новые ошибки скриптов. В Switch используется отдельная адаптация хранения uniform-параметров.

После установки проверить подключения по очереди и одновременно, перемещение через границы чанков, воду, смерть/возрождение, выход и повторный вход. Для измерения FPS нужен один и тот же участок без разгона. Стабильные 60 FPS и работа четырёх физических Switch пока не подтверждены.
