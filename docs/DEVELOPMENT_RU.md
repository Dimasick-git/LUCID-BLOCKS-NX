# Lucid Blocks NX

Локальная адаптация купленной Steam-версии Lucid Blocks 5.2.0 для Nintendo Switch / Horizon.

Оригинальная игра использует Godot 4.6 с двойной точностью. Порт собирается на Switch-ветке Godot 4.7.3 rc с GLES compatibility и статически подключённым воксельным модулем автора. Это первая тестовая сборка: запуск и производительность на консоли ещё не подтверждены.

## Состав

- `engine_modules/lucid_nx` — загрузка статического GDExtension через менеджер расширений движка.
- `native` и `platform/scons` — сборка исходного gdblocks и godot-cpp под ARM64/double.
- `patches/main` — адаптации скриптов и шейдеров игры.
- `patches/drivers`, `patches/platform`, `patches/servers`, `patches/engine` — изменения движка.
- `forwarder` — nx-hbloader с отдельным Title ID `0100963461C50000` и оригинальной иконкой игры.
- `tools` — извлечение и проверка PCK, подготовка исходников, сборка и упаковка.

Ресурсы игры, ключи, DLL и готовые игровые пакеты в этот исходный проект не входят. Установка Steam остаётся неизменной. Рабочие данные находятся в `C:/Users/dimas/lucid-build`.

## Адаптации

Сохранены исходные игровые сцены и логика. Steam отключён; начальный профиль использует лимит 60 FPS, масштаб 100%, дальность 32 и сниженные эффекты. Сохранённые пользовательские значения имеют приоритет. Указанный лимит не означает подтверждённые 60 FPS.

Меню использует программный курсор, сенсорный ввод и Nintendo A для подтверждения / B для возврата. Обозначения кнопок в настройках адаптированы; оригинальные обучающие изображения пока содержат обозначения ПК.

Шейдеры воды, неба и переходов учитывают GLES-координаты глубины. Вместо отсутствующей compute-текстуры глубины используется штатная depth texture. Параметры объектов в Switch-рендере хранятся в RGBA32UI-текстуре, обходя малый предел GLES UBO. Это сохраняет int/bool/float без потери битов. Графическое соответствие оригиналу ещё нужно проверить на консоли.

## Сборка

Точные ревизии — в `port.json`. Нужны devkitA64/libnx/portlibs, Python 3.11, SCons 4.10.0, локально восстановленный проект и исходный PCK. Движок собирается в один поток из-за 8 ГБ памяти на рабочем ПК.

```powershell
python tools/build_native.py
python tools/prepare_engine.py
C:/Users/dimas/lucid-build/venv/Scripts/python.exe tools/build_engine.py
python tools/package_game.py
python tools/package_forwarder.py --keys <локальный-путь-к-prod.keys>
python tools/assemble_sd.py
```

`prepare_project.py` создаёт отдельную рабочую копию восстановленного проекта и применяет зафиксированные патчи. Скрипты подготовки отказываются перезаписывать существующие игровые пакеты. Ключи упаковщика читаются только локально.

## Проверки

```powershell
python -m unittest discover -s tools -p "test_*.py"
python tools/validate_native.py
C:/Users/dimas/lucid-build/venv/Scripts/python.exe tools/check_global_uniform_gpu.py
```

Проверены архитектура и ABI двух статических библиотек, совместная перемещаемая линковка, чтение и контрольные суммы ресурсов PCK. Текущие скрипты прошли headless-запуск на оригинальном ПК-движке без новых ошибок; исходное предупреждение о ресурсе при выходе сохраняется. Алгоритм целочисленного хранения параметров проверен на GPU ПК, включая крайний индекс и частичное обновление. Это не проверка GPU Switch.

Форвардер проверяется повторным чтением упакованного NSP: NCA/PFS/IVFC, исходный NSO, Title ID, NPDM, тип приложения и права памяти. Журналы и результаты находятся в `lucid-build/reports`.

## Комплект для карты

`release/SD_ROOT` формируется после успешной сборки NRO. В нём находятся `/switch/lucid-blocks/lucid-blocks.nro`, `game.pck`, инструкция, лицензии и NSP-форвардер в корне. NSP запускает файлы с карты и сам игровых ресурсов не содержит. Установка через DBI выполняется на консоли.

Сохранения: `/switch/lucid-blocks/LucidBlocksNX/`; журнал запуска: `/switch/lucid-blocks/boot.log`. При обновлении сохранять личные данные. Последовательность первой проверки описана в `docs/SD_README.txt`.

Адаптация: Dimasick-git. Оригинальная игра и игровые ресурсы принадлежат их авторам.

Исправления BOOTFIX01–04 устраняют ошибки служб частот, загрузки внешнего пакета, регистрации классов и генерации TLS-кода. Аппаратный прогон OPT01 подтвердил загрузку мира и сохранение; производительность пока требует доработки.

OPT01: после аппаратного OOM в Jolt уменьшен пул чанков (32 блока), очередь готовящихся мешей ограничена четырьмя. После загрузки освобождаются временные массивы геометрии, при выгрузке — старые GPU-меши. Полный canvas-items viewport снимает ограничение 300×256; dithering выключен. Одноразовая миграция применяет минимум графики также к старой установке, сохраняя звук, управление и сохранения. Рендер — 100%; частоты остаются системными. Производительность OPT01 на консоли ещё не измерена.

OPT02: в длительном прогоне обнаружены 48 512 повторов ошибки локальных теней GLES. На Switch отключены тени точечных и прочих локальных источников до подготовки проходов. Обход воды и огня ограничен загруженной областью: при радиусе 32 вместо 1458 проверок координат за такт выполняются 250. Частота симуляции сохранена. Раз в пять секунд журнал `[nx-perf]` фиксирует время кадров, физики и обработки сцены, число вызовов отрисовки и расход памяти. Пользовательский масштаб рендера сохраняется. Прирост FPS требует проверки на консоли.

OPT03: материалы блоков используют матовое освещение без отдельных текстур металличности и шероховатости. У непрозрачного ландшафта убрано косметическое отсечение пикселей при эффекте drug; сам цветовой эффект сохраняется и пропускается при нулевой интенсивности. Основные текстуры, геометрия и коллизии сохранены. Три шейдера прошли компиляцию и отрисовку на GPU ПК; скорость на Switch ещё не проверена.

Встроенный производитель SaltyNX публикует FPS после успешного EGL present и читает лимит FPSLocker через тот же ограничитель движка. ABI проверяется при компиляции. Служба и общая память необязательны: при их отсутствии игра продолжает работать. Частота дисплея только читается, заголовок общей памяти не перезаписывается. `[nx-stage]` разделяет затраты скриптов, синхронизации и отрисовки/показа; `heap_reserved_MiB` обозначает резерв процесса, `cpu_allocated_MiB` — учтённые движком выделения, без памяти драйвера GPU.

OPT04: прогон OPT03 подтвердил подключение SaltyNX с частотой дисплея 60 Гц. На карте обнаружены 105 файлов кеша с 349 пустыми программами. Движок теперь запрашивает сохраняемый бинарник до линковки GLES-программы; лог `[nx-shader-cache]` показывает поддержку драйвера и фактический размер бинарника. Механизм сохранения и восстановления проверен на GPU ПК; поддержка бинарников драйвером Switch требует проверки новым запуском.

Меши предметов с общей иконкой переиспользуются. Сгенерированные меши сохраняются в `user://cache/item_mesh_v1/` с ключом по пикселям, размеру и формату изображения. Отсутствие кеша возвращает обычную генерацию; кеш не содержит сохранений мира. `[nx-startup]` разделяет загрузку ресурсов, создание атласа, иконок/мешей и загрузку сцен. При первом заполнении кеша часть прежних затрат остаётся.
