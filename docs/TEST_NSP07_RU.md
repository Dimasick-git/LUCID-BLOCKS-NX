# Проверки NSP07

## Воспроизведённые проблемы

- В игровом луче гостя не выбирался существующий сетевой моб. После исправления проверяется выбор цели через настоящий `Player.get_interact_data`, затем вызов игрового `Attack.attack` и подтверждение изменения здоровья хостом.
- Вариант внешности захватывался преимущественно для первого получателя. Проверка смешанной группы на хосте и трёх клиентах теперь сверяет варианты моделей, цвета, блок мимика и параметры ядра Kodama на каждом клиенте.
- Отдельный прогон мимика завершался с `0xc0000005`; в журнале оставались пять неосвобождённых Rendering Instance RID. В коде создания ног найдены неиспользуемые `MeshInstance3D` со сферами, которые никогда не добавлялись в сцену и не удалялись. После удаления этого кода оба процесса завершились с кодом 0; осиротевшие узлы — 0 → 0. Та же утечка устранена у Hwobbb.

Использовались настоящие процессы оригинального Windows-движка с адаптированным пакетом и отдельными пользовательскими каталогами. Для боевого теста создавалась изолированная площадка с полом; это не измерение производительности обычного игрового мира.

Оставшиеся сообщения исходного Windows GLES-рендера об ограничении instance uniforms отделены от ошибок скриптов. Проверки отклоняют ошибки скриптов, ошибки захвата удалённых объектов таймерами и ненулевой код завершения процесса.

## Что требует Switch

Новый аппаратный запуск, внешний вид в целевом GLES-драйвере и сравнение FPS/рывков на том же участке. Снижение числа лишних операций и устранение утечки подтверждены кодом и проверками; численный прирост FPS на устройстве не заявляется.

Для следующего отчёта нужны строки `[nx-perf]`, `[nx-stage]` и `[nx-net]` из `boot.log` обеих консолей. Последние показывают среднюю стоимость сетевого снимка, число и стоимость созданий мобов и размер очереди появления.
